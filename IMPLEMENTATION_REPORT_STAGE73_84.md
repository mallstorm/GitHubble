# GitHubble 0.26.0 — этапы 73–84

Версия: `0.26.0-beta-stage73-84`  
Package: `app.githubble.mobile`  
minSdk: 28  
target/compileSdk: 36

## 73. Создание Pull Request

Добавлен нативный сценарий создания Pull Request:

- загрузка доступных веток репозитория;
- выбор исходной и целевой веток;
- заголовок и Markdown-описание;
- создание draft PR;
- проверка, что ветки различаются;
- переход к созданному PR после ответа GitHub.

## 74. Ревью Pull Request

На детальном экране PR доступны:

- обычный review-комментарий;
- `APPROVE`;
- `REQUEST_CHANGES`;
- отображение существующих reviews и их статусов;
- повторная загрузка PR после успешной операции.

## 75. Слияние Pull Request

Добавлен диалог merge:

- разрешённые методы читаются из настроек репозитория;
- поддерживаются merge commit, squash и rebase;
- необязательные заголовок и описание merge-коммита;
- передаётся актуальный SHA головы PR;
- серверные branch protection/checks остаются окончательным источником решения.

## 76. Метки, исполнители и milestones

Для Issues и Pull Requests реализовано управление:

- labels;
- assignees;
- milestone;
- сохранение выбранного набора через GitHub Issues API;
- обновление экрана после записи.

## 77. Star, follow и наблюдение

Реализованы:

- star/unstar репозитория;
- follow/unfollow разработчика;
- отдельное локальное наблюдение GitHubble за разработчиком и его новыми репозиториями.

Нативная GitHub-команда Watch не отправляется: endpoint изменения repository subscription не поддерживает GitHub App user access tokens. Вместо неработающей кнопки оставлен собственный центр наблюдения GitHubble.

## 78. Единый офлайн-кэш объектов

Создан `EntityCache` на SQLite:

- кэшируются профили, репозитории, Issues, PR, Releases и содержимое;
- сохраняются payload, ETag, время создания и TTL;
- GET использует `If-None-Match` и ответ `304`;
- при сетевой ошибке или временном ответе 5xx/429 используется сохранённая версия;
- ошибки прав 403/404 не маскируются устаревшим кэшем;
- лимит — 1200 последних записей;
- статистика и очистка доступны в настройках.

## 79. Восстановление состояния

Добавлен `ScreenStateStore`:

- сохраняет активный маршрут и аргументы;
- восстанавливает профиль, настройки, наблюдение, репозиторий, Issues, PR и Releases;
- сохраняет вертикальную позицию прокрутки;
- использует `savedInstanceState` и резервное локальное состояние;
- не сохраняет токен или API-ключ в Bundle.

## 80. Декомпозиция MainActivity

Из Activity вынесены use-case контроллеры:

- `RepositoryController`;
- `ProfileController`;
- `TranslationController`.

Сетевые операции, изменение репозиториев, профиль и конфигурация перевода больше не сосредоточены полностью в UI-классе.

## 81. Проверки авторизации и пагинации

Добавлены:

- dependency-free instrumentation runner;
- проверки нормализации Device Flow-кода;
- проверки запрета параллельной двойной загрузки страницы;
- REST page progression;
- GraphQL cursor progression;
- отдельный JVM regression runner.

Instrumentation APK успешно собран. На физическом устройстве тесты не запускались, поскольку в среде сборки отсутствовал подключённый Android-девайс или эмулятор.

## 82. Accessibility и крупный шрифт

Выполнено:

- увеличенная высота интерактивных элементов при fontScale ≥ 1.25;
- адаптивная межстрочная высота;
- content description для ключевых действий;
- предотвращение слишком плотной сетки при крупном шрифте;
- сохранение читаемого контраста во всех трёх темах.

## 83. Планшеты и адаптивная компоновка

Добавлены правила:

- 3–4 колонки на широких экранах;
- ограничение ширины контента до 900 dp;
- центрирование основного полотна;
- адаптивные статистические и action-сетки;
- более свободные верхняя и нижняя панели на планшетах.

## 84. Воспроизводимая beta-сборка и диагностика

Реализовано:

- `build-reproducible.sh` без встроенных секретов;
- отдельная проверка двух чистых сборок;
- два clean build дали байт-в-байт одинаковый unsigned APK;
- повторная подпись одного и того же APK дала одинаковый signed APK;
- экспорт диагностического ZIP в `Downloads/GitHubble`;
- в диагностику не попадают GitHub token, API-ключ переводчика, пароль или signing key;
- подготовлен release checklist.

## Совместимость обновления

APK подписан сертификатом ветки `0.25+`. Он может обновить основную GitHubble 0.25.0 с package `app.githubble.mobile`. Версии 0.24 и более ранние, подписанные другими сертификатами, требуют отдельной установки/перехода.

## Ограничения

- Все операции записи зависят от разрешений GiHubble и прав пользователя в конкретном репозитории.
- GitHub может отклонить merge из-за branch protection, required checks или отсутствия прав.
- Instrumentation tests собраны, но не запущены на реальном Android.
- MainActivity всё ещё крупная; декомпозиция начата, но перед stable 1.0 должна быть продолжена.
