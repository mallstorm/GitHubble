## 85. Офлайн-очередь действий

Добавлена долговечная SQLite-очередь `OfflineActionQueue`:

- сохраняет replay-safe изменения без OAuth-токена;
- автоматически отправляет их после восстановления сети;
- повторяет временные ошибки сети, HTTP 408, 429 и 5xx;
- использует ограниченный экспоненциальный backoff;
- после шести неудачных попыток переводит действие в состояние ошибки;
- объединяет ожидающие изменения одного объекта по `entityKey`;
- показывает очередь в `Настройки → Данные → Офлайн-очередь`.

В очередь подключены редактирование Issue и изменение labels/assignees/milestone. Архитектура допускает подключение остальных replay-safe операций без хранения секретов.

## 86. Конфликты синхронизации

Перед повторной отправкой GitHubble запрашивает текущую версию объекта и сравнивает поле `updated_at` с базовой версией:

- несовпадение переводит действие в `CONFLICT`;
- пользователь видит локальный JSON и актуальный серверный снимок;
- доступны варианты «Отправить локальную версию» и «Оставить версию GitHub»;
- конфликты 409, 412 и 422 не повторяются автоматически вслепую.

## 87. Создание объектов репозитория

Добавлен `RepositoryAdminController` и нативные сценарии:

- создание публичного или приватного репозитория;
- необязательная инициализация README;
- fork в личный аккаунт или организацию;
- создание ветки от ветки, тега или SHA;
- создание lightweight tag;
- создание Release с draft, prerelease и generated notes.

Точка входа: карточка репозитория → `Управление`; новый репозиторий создаётся со страницы «Мои репозитории».

## 88. Расширенная работа с Pull Request

Добавлен `PullRequestAdvancedController`:

- комментарий к конкретной строке diff;
- корректные `path`, `line`, `side` и актуальный head SHA;
- GitHub suggested change через блок `suggestion`;
- объединённый просмотр commit statuses и check runs;
- чтение required status checks целевой ветки, когда GitHub разрешает доступ;
- переход к внешней странице конкретной проверки.

## 89. Split diff и навигация

Добавлен парсер `DiffModel` и два режима:

- Unified;
- Split.

Также реализованы:

- переход к предыдущему/следующему изменённому файлу;
- сворачивание длинных блоков контекста;
- ограничение отображаемых строк для защиты памяти;
- цветовое разделение добавлений и удалений;
- нажатие на изменённую строку для комментария или suggested change;
- сохранение выбранного режима между запусками.

## 90. Безопасный просмотр файлов

`FilePreviewController` классифицирует файл до отображения:

- текст и исходный код;
- PNG/JPEG/WebP/GIF/BMP;
- SVG;
- PDF;
- бинарный файл;
- слишком большой файл.

Реализованы встроенный просмотр изображений, исходный просмотр SVG, безопасная передача PDF/бинарных файлов системному загрузчику или GitHub и лимит 12 МБ для загрузки в память. Бинарные данные больше не интерпретируются как текст.

## 91. Перенос локальных данных

Добавлен JSON-экспорт/импорт через системный Storage Access Framework:

- избранные репозитории;
- список наблюдаемых разработчиков;
- тема, иконка и пользовательские настройки;
- параметры фонового наблюдения;
- настройки diff.

Намеренно исключены OAuth-токен, API-ключ переводчика, профильный кэш, диагностика и signing material. Импорт объединяет данные, а не стирает существующие.

## 92. Декомпозиция нового функционала

Новые функции вынесены из сетевого и предметного слоя Activity:

- `OfflineActionQueue`;
- `OfflineMutationDispatcher`;
- `RepositoryAdminController`;
- `PullRequestAdvancedController`;
- `DiffModel`;
- `FilePreviewController`;
- `PortableSettingsManager`;
- `FeatureControllerRegistry`;
- `FeatureUiState`.

`MainActivity` остаётся Android Platform UI shell и отвечает за маршрутизацию/рендеринг. Новые предметные операции, SQLite, diff-парсинг, preview-классификация и backup-формат внутри неё не реализуются. Полное дробление всех исторических экранов остаётся задачей стабилизационного прохода.
