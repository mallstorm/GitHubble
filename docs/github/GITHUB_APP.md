# GitHub App (ТЗ §8.3) — статус по пунктам

| Требование ТЗ | Статус |
|---|---|
| Идентичность приложения | PARTIAL: вход через OAuth Device Flow с `GITHUB_CLIENT_ID`, заданным при сборке; приложение читает установки через `user/installations` (этот маршрут отвечает для пользовательских токенов GitHub App). Что именно зарегистрировано у владельца (GitHub App или OAuth App), в этом проходе **не проверялось** |
| Installation authentication (токен установки, бот-идентичность) | MISSING: нужен приватный ключ приложения, его нельзя хранить в мобильном клиенте; требует серверной части (см. REMOTE_RUNTIME) |
| Минимально необходимые permissions | PARTIAL: для реализованных инструментов нужны Contents, Pull requests, Issues, Actions (read, write для запуска), Metadata (read); для изменения файлов `.github/workflows` — Workflows. Матрица и проверка прав в коде не автоматизированы |
| Только разрешённые репозитории | WORKING: инструменты работают только с привязанным репозиторием; `download_artifact` и `artifact_verdict` отклоняют чужие |
| Commits/PR с корректной атрибуцией | WORKING (от пользователя): коммиты и PR создаются токеном пользователя; поля автора/коммиттера не подменяются (в коде нет переопределения author/committer, проверено поиском). Бот-атрибуции нет |
| Комментарии от идентичности приложения | MISSING: `comment_issue` пишет от имени пользователя |
| Управление доступом к установленным репозиториям | PARTIAL: `github_capabilities` показывает установки и ссылку на настройки GitHub; изменять доступ агент не может |

Правило ТЗ соблюдено: агент не называет себя ботом GitHub и не подменяет имя автора; без установки App используется пользовательская авторизация,
автор — пользователь.
