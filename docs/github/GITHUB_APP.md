# GitHub App (ТЗ §8.3) — статус по пунктам

| Требование ТЗ | Статус |
|---|---|
| Идентичность приложения | PARTIAL: вход через OAuth Device Flow с `GITHUB_CLIENT_ID`, заданным при сборке; приложение читает установки через `user/installations` (этот маршрут отвечает для пользовательских токенов GitHub App). Владелец подтвердил (скриншоты настроек GitHub): зарегистрирован **GitHub App «GiHubble»**, установлен на аккаунт mallstorm на все репозитории; вход по Device Flow устанавливает App и выдаёт пользовательский токен (user-to-server). Эффективные права = пересечение прав App и прав пользователя |
| Installation authentication (токен установки, бот-идентичность) | НЕ ТРЕБУЕТСЯ (решение владельца 2026-11-11: вся работа идёт через пользовательский токен App «GiHubble», отдельная идентичность бота не нужна). Для справки: потребовала бы приватный ключ приложения (его нельзя хранить в мобильном клиенте) и серверную часть |
| Минимально необходимые permissions | PARTIAL: для реализованных инструментов нужны Contents, Pull requests, Issues, Actions (read, write для запуска), Metadata (read); для изменения файлов `.github/workflows` — Workflows. Матрица и проверка прав в коде не автоматизированы |
| Только разрешённые репозитории | WORKING: инструменты работают только с привязанным репозиторием; `download_artifact` и `artifact_verdict` отклоняют чужие |
| Commits/PR с корректной атрибуцией | WORKING (от пользователя): коммиты и PR создаются токеном пользователя; поля автора/коммиттера не подменяются (в коде нет переопределения author/committer, проверено поиском). Бот-атрибуции нет |
| Комментарии от идентичности приложения | MISSING: `comment_issue` пишет от имени пользователя |
| Управление доступом к установленным репозиториям | PARTIAL: `github_capabilities` показывает установки и ссылку на настройки GitHub; изменять доступ агент не может |

Правило ТЗ соблюдено: агент не называет себя ботом GitHub и не подменяет имя автора; без установки App используется пользовательская авторизация,
автор — пользователь.

## Наблюдение о правах (не изменено)
У установленного App включены права записи сверх используемых инструментами (administration, secrets, repository hooks, security events,
agent tasks и др.), доступ — «All repositories». Ни один реализованный инструмент их не использует. Сужение прав — решение владельца
(в настройках App; пользователь затем подтверждает обновление прав). Сужать стоит только после проверки, что Device Flow и инструменты
(Contents, Pull requests, Issues, Actions, Workflows, Metadata) продолжают работать.
