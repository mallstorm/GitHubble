## Изоляция и изменения

`WorkspaceSource` — общий read-only источник: GitHub, локальный Workspace или SAF
через существующие `WorkspaceHub → WorkspaceEngine → WorkspaceTools → ProjectFileSystem`.
`TaskGitService` фиксирует Project/Task, источник и commit. `ChangeStore` хранит только
изменения текущей задачи в отдельном каталоге, вычисленном из account/project/task.
Пути проектов, SAF и файлы других задач агент не перезаписывает.

Состояния ChangeSet и отдельных файлов:
`PROPOSED → APPROVED → LOCAL_APPLIED → PUBLISHED`, дополнительно `REJECTED`,
`CONFLICT`, `ROLLED_BACK`. При частичной приёмке состояние набора агрегируется из
состояний файлов: в дельту попадают только LOCAL_APPLIED.

LOCAL_APPLIED означает применение к приватному overlay задачи. Общая рабочая копия
остаётся базой. Чтение файлов задачи объединяет её базу и подтверждённый overlay.
Это позволяет держать несколько задач одного проекта и не переносить неподтверждённые
предложения между ними. После публикации задача читает новый подтверждённый commit;
опубликованные операции остаются в истории и больше не перекрывают новую базу.

Перед предложением нужен expected_sha из read_file; перед применением повторно
проверяются и эта ревизия, и исходный SHA базы. SHA файлов — настоящий Git blob SHA
с заголовком типа/размера. Защищённые пути, symlink, бинарные данные и известные секреты
блокируются; содержимое с секретами требует ручного редактирования.

Перед первым предложением и каждым применением сохраняется checkpoint метаданных
задачи. Применение атомарно переключает manifest, исходники и SAF не затрагивает.
Откат исключает операции из overlay; более поздние зависимые правки того же файла
сначала нужно отменить. Опубликованное изменение отменяется новым ChangeSet.
Удаление задачи удаляет её приватные изменения, сохраняя проект и GitHub.

## Единый файловый интерфейс

`WorkspaceToolset` предоставляет:

- список файлов с offset/limit и явным количеством исключённых защищённых путей;
- чтение диапазона до 500 строк / 20000 символов, с SHA и признаком усечения;
- поиск страницами по 32 файла, с указанием пропущенных/непрочитанных файлов;
- Project Map и ленивые symbol_index/find_definition/find_usages через существующий
  ProjectIndex, только по явно выбранной странице до 32 исходников;
- создание, точную однократную замену, строгий single-file unified patch;
- удаление, rename/move файлов и каталогов как атомарные группы путей;
- создание пустых каталогов внутри представления задачи.

Контекстные заголовки, позиции и размеры блоков unified patch проверяются точно,
без fuzzy matching. Diff поддерживает отдельную приёмку файлов и блоков, включая
изменение финального перевода строки. Для очень большого несовпадающего диапазона
используется один укрупнённый блок; неизменные префикс/суффикс исключаются из сравнения.
Git не хранит пустые каталоги: они остаются локальной структурой задачи, пока в них
не появятся файлы.

Файловые операции ограничены 2 MiB на файл, 4 MiB на пакет и 100 затрагиваемыми путями
на ChangeSet. Каталоги большого размера изменяются меньшими пакетами. Важен размер
дельты, а не общее число файлов репозитория.

## Remote-first и импорт

GitHub-дерево читается на зафиксированном commit SHA. Blob загружается только для
запрошенного файла; наличие репозитория не создаёт Workspace и не импортирует его
целиком. Если локальный снимок соответствует тому же commit, безопасные файлы могут
читаться из существующего backend; пропущенные файлы доступны через GitHub по запросу.

`ZipballImporter` используется только при явном импорте. Загрузка потоковая, с
сохранением в ограниченный временный файл. Распаковка идёт в новый staging-каталог,
который устанавливается только после полной проверки. Старый Workspace не заменяется.
Проверяются central directory, размеры, CRC, единый корень, traversal/absolute paths,
коллизии путей, Unix special files/symlink, encryption и предел распаковки.
ZIP64 и multi-disk не входят в допустимый ограниченный формат.

Настройки по умолчанию: 32 MiB ZIP, 10000 записей, 32 MiB текста, 64 MiB распаковки,
1 MiB на импортируемый файл. Верхние предохранители: 200 MiB ZIP, 20000 записей,
150 MiB текста. Это верхние ограничения, а не целевые размеры импорта.
Бинарные, защищённые, содержащие известные секреты и превышающие текстовый бюджет
файлы пропускаются. Причины и частичность сохраняются в локальной карте импорта;
Project Map передаёт счётчики причин и безопасные примеры пропусков.

GitHub credential используется только на API-запросе zipball. Redirect допускается
только на codeload.github.com для того же репозитория/SHA, без передачи Authorization.

## Ветка, дельта и сверка

`TaskBranch` создаёт отдельную `hubble/<slug>-<task-id>`. Существующая чужая ветка
не присваивается задаче. Намерение создания и подтверждение ref сохраняются до/после
API-вызова. Неподтверждённая операция не повторяется автоматически.

`DeltaPublisher` публикует только подтверждённую дельту:

- ADD/MODIFY создают blobs;
- DELETE использует tree entry с sha:null;
- RENAME — удаление прежнего и добавление нового пути в одной tree transaction;
- дерево строится от base_tree фактического родительского commit;
- существующий executable mode сохраняется;
- main/master и защищённые ветки запрещены, force всегда false.

`RemoteSync` сравнивает затрагиваемые пути с текущим HEAD. Если удалённая ветка
сдвинулась по другим файлам, новая tree/commit строится от её актуального HEAD.
Пересечение изменений блокирует запись до создания blobs. Непосредственно перед
изменением ref HEAD проверяется ещё раз, после операции ref перечитывается.
Только совпадение с созданным commit сохраняет CONFIRMED.

На время публикации overlay заморожен. Журнал фиксирует PREPARING и REF_UPDATE_PENDING
до мутаций. Неопределённый ответ оставляет UNKNOWN и запрещает повтор даже с другим
commit message. «Сверить ref» выполняет только чтение; при совпадении завершает
локальную фиксацию результата. Если достоверно остановились до обновления ref,
и ref остался прежним, сверка может безопасно снять блокировку.

Старые прямые методы commitApprovedPlan/publishApprovedWorkspace удалены после
замены всех production-вызовов. Ручные кнопки генерации и публикации используют
тот же task pipeline. Нет fallback к загрузке всего Workspace.

## Интерфейс

«Изменения задачи» доступны из инструментов чата, Project Hub и настроек.
В REVIEW предложение остаётся PROPOSED до явного принятия. Можно принять весь набор,
файл или выбранные блоки; rename-группа принимается/отклоняется целиком.
Work panel показывает diff, состояния, откат и preview дельты перед публикацией.
Чувствительные workflow остаются на ручном review даже в AUTO.

Вкладка «Файлы» панели «Код» использует рабочее представление задачи, поддерживает
пагинацию и чтение по строкам, включая проект GitHub без локального Workspace.
Старый ручной LocalShell сохраняется отдельно, без доступа из ToolBroker.

## Проверка и приёмка

```sh
./gradlew --no-daemon test assembleDebug assembleRelease lintRelease assembleDebugAndroidTest
```

Новые наборы: WorkspaceToolsetTest, ChangeStoreTest, DeltaPublisherTest,
ZipballImporterTest. Они проверяют изоляцию/перезапуск overlay, SHA-конфликты,
принятие файла/блока, rollback, удаления/rename/каталоги, ленивый индекс, секреты,
три изменённых файла среди тысяч, сохранение других blobs, сдвиг HEAD, UNKNOWN без
повторной мутации, zip-slip, symlink, zip-bomb и частичный импорт.

Android Agent chat UI проверяет, что native tools пишут в overlay, а общие файлы
не меняются. ChangeReviewUiChecks нажимает настоящие элементы review и принимает
только первый из двух блоков. RC instrumentation, Account UI и minified Xray smoke
остаются обязательными. CI использует фейковые аккаунты и провайдеры.

На устройстве остаются SAF, реальные аккаунты/приватные репозитории и проверка
провайдеров. Полный CI repair/Supervisor/Evidence, финальный UI и подписанный релиз
относятся к отдельному этапу III.
