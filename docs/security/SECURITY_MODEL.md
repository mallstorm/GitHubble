# Модель безопасности

- Секреты: Android Keystore (AES-GCM) через `SecureStore`; не пишутся в журналы и память проекта.
- Аккаунт: операции агента привязаны к активной сессии под `SESSION_LOCK`; смена аккаунта прерывает операцию (D1 исправлен в Git-workspace, диагностике и загрузке артефактов).
- Модель не получает произвольных URL/методов — только каталог инструментов; аргументы валидируются хостом.
- Опасные действия всегда требуют отдельного подтверждения (`ExecutionMode.DANGEROUS`; в боевом пути — уровни разрешений и ревью).
- Бюджет сборок и автоисправлений ограничен хостом; сбои биллинга/прав/подписи не «обходятся».
## Проверки прохода F (факты)
- Манифест не менялся: новые разрешения не добавлены; `allowBackup="false"`.
- Поиск секретов в добавленных строках: единственное совпадение — тестовая строка `BEGIN RSA PRIVATE KEY` в `SupervisorTest` (ложное срабатывание, проверяет маскирование).
- Журнал запуска (`AgentRunJournal`) хранит имена инструментов, состояния и отпечаток аргументов, но не сами аргументы и не результаты (`SecurityPropertiesTest`).
- `JournalStore` отвергает идентификаторы с `..`, `/`, нулевым символом, пустые.
- APK, скачанный агентом, публикуется в Загрузки только после проверки целостности, пакета, версии и подписи.
- Уведомления агента не содержат содержимого задач и показываются только при свёрнутом приложении.
