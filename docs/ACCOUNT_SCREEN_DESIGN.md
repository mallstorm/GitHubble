# Унификация экранов управления аккаунтом

RC4.2.30 (77). Основа — существующие SettingsScreen и HomeScreen.Palette, используемые в основных настройках приложения.

- Главная страница управления: штатный заголовок, группы строк с иконками и подписями, краткие карточки доступных установок.
- Права установки открываются отдельно: понятные названия, группы по назначению и уровни «Только чтение», «Чтение и изменение», «Нет доступа» или «Уровень не определён». Отсутствие сведений не трактуется как разрешение.
- Нет сырого JSON и сплошных полноширинных зелёных кнопок.
- Общая верхняя панель растёт по содержимому при крупном шрифте; подписи нижних вкладок помещаются по ширине. Контраст системных значков согласован с темой.
- Блокировки и ограничения используют тот же SettingsScreen; выбранный режим ограничения соответствует текущему значению.
- Вложенные страницы аккаунта отмечают вкладку «Настройки» в общей нижней навигации.
- Новая навигация сохраняется после пересоздания Activity. Привязка запросов к аккаунту и защита устаревших ответов сохранены.

Визуальная проверка: debug-only AccountAccessPreviewActivity использует настоящий MainActivity.shell и production AccountAccessScreen на синтетических установках demo-user/example-maintainer. Требуется чистый тестовый профиль без GitHub-токена. В Release fixture отсутствует.

Workflow Account access UI проверяет переход в права, отсутствие JSON, три палитры и font_scale 1.0/1.5 на Android 13. Сохраняются 18 снимков: верх страницы, список установок, права. Чтобы не зависеть от заполненной квоты Actions artifacts, снимки публикуются в изолированную ветку preview/account-ui-<head SHA>; исходная ветка приложения не меняется. Форки не получают этот шаг публикации.

Реальные операции пользователя и проверка действительных GitHub grants этим визуальным тестом не выполняются.
