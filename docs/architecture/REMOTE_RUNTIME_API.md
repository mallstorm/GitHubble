# Remote Runtime — контракт API (ПРОЕКТ, не реализовано)

Этот документ описывает предполагаемый контракт из ТЗ §12.3. Ни клиент, ни сервер его не реализуют.

Принципы: TLS 1.2+, аутентификация короткоживущим токеном устройства, привязанным к аккаунту GitHub; минимальные полномочия
(только выбранные репозитории); подтверждения (approval) пользователя передаются как отдельные подписанные события;
секреты провайдеров не возвращаются клиенту; журналы проходят `AgentLogRedactor`.

| Операция | Метод и путь (проект) | Тело/ответ (суть) |
|---|---|---|
| Создать задачу | `POST /v1/tasks` | repo, ветка, цель, режим → `task_id`, состояние CREATED |
| Состояние | `GET /v1/tasks/{id}` | состояние из `TaskState`, режим, бюджет сборок, список вызовов (`ToolLedger`) |
| Пауза / продолжить / отмена | `POST /v1/tasks/{id}/pause|resume|cancel` | идемпотентно; переходы валидирует `TaskJournal` |
| Согласование | `POST /v1/tasks/{id}/approvals/{op}` | решение пользователя; без него операция остаётся в WAITING_PERMISSION |
| Журнал | `GET /v1/tasks/{id}/events?after=seq` | события `TaskJournal` (STATE, MODE, NOTE, APPROVAL) |
| Артефакты | `GET /v1/tasks/{id}/artifacts` | ссылки + вердикт проверки APK |
| Синхронизация проекта | `POST /v1/projects/{id}/sync` | только метаданные и подтверждённые изменения |

Повторяемость: каждый вызов изменения несёт `operation_id`; сервер применяет `ToolLedger`-семантику (повтор успешной операции отклоняется).
Соответствие существующим классам: состояния — `TaskState`, политика — `ExecutionMode`, повторы сборок — `RetryPolicy`,
приёмка результата — `Supervisor` и `ArtifactVerifier`. Эти классы чистые (Java без Android) и могут исполняться на сервере без изменений.
