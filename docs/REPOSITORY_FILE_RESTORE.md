# GitHubble — восстановление одного файла из истории

## Используем существующий интерфейс

Откройте репозиторий → Управление → Коммиты → выберите исторический коммит.
В уже реализованном экране CommitDetailScreen раскройте diff файла и нажмите
**«Восстановить эту версию через PR»**.

Это отдельная операция на уровне файла, а не полное зеркалирование Git-истории,
откат всей ветки или новый файловый редактор. Существующий CommitDetailController
и просмотр diff остаются без изменений.

## Проверка перед записью

- Авторизованный подключённый аккаунт должен соответствовать владельцу репозитория.
- Приложение проверяет `Contents: write`, отсутствие архивирования и SHA текущей default branch.
- Исторический Git tree обходится по отдельным каталогам. Неполное или повреждённое дерево не принимается за полный результат.
- SHA-1 содержимого Git blob пересчитывается и сверяется с GitHub; файл ограничен 1 МиБ.
- Символические ссылки, submodules, служебные workflows, ключи и LFS pointers отклоняются.
- Если файл отсутствует в выбранном коммите — предлагается выбрать более ранний коммит.
- Если содержимое и executable mode уже совпадают, пустой PR не создаётся.
- Перед записью повторно проверяются Git SHA, файл, разрешения и branch HEAD.

## Публикация результата

Создаётся новый Git tree поверх HEAD, один Git commit, новая ветка
`restore/file-*` и **черновик Pull Request**. Основная ветка остаётся
неизменной до явного merge пользователем. В PR выводятся путь, исходный SHA,
базовый SHA и пояснение.

При сетевом сбое после создания ветки операция не повторяется автоматически:
приложение укажет созданную ветку и попросит проверить состояние GitHub.
Для восстановленного файла из удалённого ранее пути создаётся добавление,
для изменённого — изменение. Массового восстановления и стирания файлов нет.

## Пакет разработки

Ветка `feature/repository-historical-file-restore` зависит от
`feature/repository-compare-selective-pr` (PR #69), поскольку переиспользует
авторизованный GitHub-клиент, проверку Git blob и безопасные правила путей.
Разрешения GitHub App: Contents read/write, Pull requests write.
Сквозной тест создания PR на пользовательском репозитории из CI не выполняется.
