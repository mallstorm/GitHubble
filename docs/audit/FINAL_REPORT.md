# Итоговый отчёт: GitHubble 2.0 (PR #29)

База: `2f4c9dc`, голова ветки `claude/githubble-2-pass1`. 14 коммитов, 71+ файл, около +4150/−390 строк.

## Что реализовано
- **Ядро агента** (`agent.core`, чистая Java): машина состояний задачи (17 состояний), durable-журнал, ToolLedger (защита от повторов), ExecutionMode (AUTO/SEMI/MANUAL), классификатор сбоев сборки, RetryPolicy (8 сборок / 5 исправлений / 3 transient), Supervisor с Evidence, проверка APK (целостность, пакет, версия, подпись), классификация отказов GitHub API.
- **Подключение к хосту**: журнал каждого запуска агента, защита от повторного create/merge, пометка оборванных запусков при старте, уровни разрешений ↔ режимы, обязательное ревью для чувствительных действий.
- **GitHub**: `dispatch_workflow` с проверкой workflow и триггера до подтверждения и привязкой `run_id`; `list_releases`, `create_release` (черновик по умолчанию); `download_artifact` с проверкой ожидаемых package/version.
- **Сборки**: инструменты `await_build`, `build_run_status`, `build_artifacts`, `verify_build`; APK публикуется в Загрузки только без FAIL; вердикт виден агенту.
- **UI/уведомления**: состояние задачи в панели запуска, «Продолжить с контекстом», уведомления агента (ждёт подтверждения / завершено / прервано).
- **Исправлен реальный дефект**: гонка аккаунта/сессии в `AgentGitWorkspace`, `AgentBuildDiagnostics`, `AgentBuildArtifactController`.
- Удалён неиспользуемый код (`AiConnectionStore`, `OmniChatChatGateway`).
- Документы по ТЗ §18 в `docs/` (аудит, архитектура, агент, GitHub, сборки, безопасность, тесты, changelog).

## Тесты и сборка
- Локально (JVM): 72 теста чистого ядра, все проходят.
- CI на `7376e0a`: все 4 workflow зелёные (unit, assembleDebug/Release, lintRelease, Xray smoke, Account UI, Agent chat UI). Часть прогонов перезапускалась из-за сбоев инфраструктуры (повреждённый SDK Platform 33, зависший эмулятор), не из-за кода.
- Код, зависящий от Android, проверяется только CI.
- APK из PR — отладочный «TEST DEBUG APK ONLY»; подписанный релиз собирается только на `main` (нужны секреты). В песочнице скачать артефакт не удалось (прокси блокирует blob-хранилище).

## Проверки безопасности
См. `docs/security/SECURITY_MODEL.md`: без новых разрешений, `allowBackup=false`, секретов в диффе нет, журнал не хранит аргументы.

## Не сделано / ограничения
- **Remote Runtime и бот-идентичность GitHub App не реализованы** — только анализ и проект API (`REMOTE_RUNTIME.md`, `GITHUB_APP.md`); нужно решение владельца.
- E2E-сценарии ТЗ A–C, H вживую не запускались; D–G — симуляции логики (`TEST_MATRIX.md`).
- Новые сетевые инструменты не запускались против живого GitHub.
- «Продолжить с контекстом» перезапускает задачу, цикл модели не возобновляет.
- `src-compose` не тронут; в настройках остались «призраки» `tracking_max_pages`, `tracking_release_check_limit`.
- Отдельного экрана всех задач и переключателя режимов вне диалога разрешений нет.

## Решения владельца

2. Архитектура Remote Runtime и бот-идентичность.
3. Удалять ли `src-compose`.
