# GitHubble 1.0.0-rc4.2.36

Версия кандидата 1.0.0-rc4.2.36, versionCode 83. Агент: шлюз GitHub, навыки и режим коллеги.

- Единый шлюз GitHub для агента: github_get (любое чтение api.github.com: биллинг, пакеты, кэш Actions, правила) и github_request (любая запись). Риск определяет хост: обратимое — по уровню разрешений, удаление — всегда с подтверждением, необратимое (удаление репозитория, видимость, передача, force-push, хуки, права, защита веток) — только после ввода точного имени, даже на уровне «Авто».
- Новые инструменты: delete_repository, actions_cleanup (кэш, артефакты, запуски: список, размер, одно подтверждение), ask_user (кнопки выбора с рекомендацией), record_decision (решение в память проекта), load_skill, propose_skill.
- Навыки агента: 9 встроенных, свои навыки (SKILL.md), включение в настройках, команда /имя в чате, экспорт. Навык — инструкция, а не разрешение: хост по-прежнему проверяет каждый вызов, а поле tools ограничивает изменения.
- Из подсказок убраны запреты на биллинг и удаление; единый перечень инструментов. Защита секретных путей сужена: TokenManager.java и PasswordField.kt больше не блокируются.
- Удалённый через агента репозиторий сразу пропадает из списка. Исправлены версии в README и ARCHITECTURE.

# GitHubble 1.0.0-rc4.2.33

Версия кандидата 1.0.0-rc4.2.33, versionCode 80. Unified Agent Engine: этап III.

- Сборки привязаны к commit SHA задачи; повторная отправка при неизвестном сетевом результате блокируется.
- Лимиты CI и исправлений сохраняются после перезапуска; права, квоты и подпись требуют внешних действий.
- Журналы передаются модели только после отдельного согласия на конкретную сборку.
- Завершение инженерной задачи проверяется по ref, PR, workflow и устройственному вердикту APK.
- Подпись APK проверяется криптографически, сохраняются SHA256 и сертификат.
- Общая панель задачи: обсуждение, diff, CI, подтверждённые результаты и разрешение продолжения.
- Восстановление не повторяет незавершённые мутации; история, изменения и бюджеты сохраняются.

Debug APK — для приёмки; production Release подписывается существующим main workflow после merge.
SAF, реальные OAuth/API-провайдеры, KeyDealer/Nemotron и обновление поверх старого Release проверяются отдельно на устройстве.
