# GitHubble: центр сборок и артефактов

## Работающая конфигурация (без внешнего сервера)

Откройте Репозитории → Центр сборок → Настроить. Выберите до 30 доступных репозиториев или добавьте имя `owner/repo` вручную. Включите системные уведомления Android. Запуски GitHub Actions и артефакты берутся из GitHub REST API с авторизацией текущего аккаунта; GitHub App должна иметь `Actions: Read` для приватных репозиториев.

Приложение сверяет запуски при открытии Центра сборок и через Android JobScheduler приблизительно раз в 15 минут при наличии сети. JobScheduler может отсрочить проверку из-за Doze, энергосбережения, MIUI и сетевых ограничений. Это системные локальные уведомления после проверки; без серверного push они не приходят мгновенно. Первое успешное сканирование сохраняет существующие сборки без уведомления о прошлом; последующие новые запуски, завершения и появление артефактов уведомляются с защитой от дублей.

Нажмите «↓ ZIP» у артефакта. Перед каждой загрузкой приложение запрашивает у GitHub новую короткоживущую подписанную ссылку. OAuth-токен передаётся только в `api.github.com`, а не хосту загрузки. ZIP сохраняется Android DownloadManager в «Загрузки/GitHubble». На Android 10+ после скачивания APK-файлы из ZIP автоматически извлекаются через MediaStore в ту же папку; уведомление предлагает открыть стандартный установщик. Установка требует явного согласия пользователя и, при необходимости, разрешения «Установка неизвестных приложений». Исходники, Windows ZIP и другие типы артефактов остаются оригинальными ZIP. Скачанные файлы сохраняются локально даже после истечения срока хранения артефакта на GitHub. Автосохранение Android-артефактов включается отдельно в настройках мониторинга и по умолчанию выключено. По умолчанию только ручная загрузка; автоматическая доступна лишь по безлимитной сети, для артефактов до 150 МБ с именами, содержащими APK, Android или GitHubble. ZIP сохраняется локально, APK извлекается на Android 10+. Удаление старых локальных файлов выполняется пользователем.

## Для настоящих мгновенных push

В текущем релизе FCM/Webhook **не подключены**: для настоящих push, доставляемых вне периодических проверок, необходимо подключить управляемый серверный обработчик webhook GitHub с проверкой подписи `X-Hub-Signature-256`, Firebase project и защищённые серверные credentials, регистрацию устройства и механизмы отписки. Ни Firebase service-account, ни webhook secret не следует встраивать в APK или отправлять клиентам. До подключения этой инфраструктуры монитор работает через JobScheduler. Не трактуйте локальное Android-уведомление как доставку FCM.

## Ограничения

Недостаточные разрешения GitHub App или истечение артефактов может сделать данные недоступными. Возможен лимит GitHub API (особенно при отслеживании 30 проектов). Версия с отдельным идентификатором `.debug` устанавливается рядом с основным приложением и имеет свою песочницу и свои настройки мониторинга.
