# GitHubble RC4.2.1 — реальная активность проектов

Основа: RC4.2, commit `14192b1d5c9cabd9adcb20113ded56ee13f94236`.
Версия: `1.0.0-rc4.2.1`, versionCode `48`.

## Интерфейс
- В Центре сборок убрана кнопка «Настроить». Доступна кнопка «Обновить», а все настройки мониторинга по-прежнему находятся в разделе настроек приложения.
- Удалён блок из пяти недавних репозиториев с главной. Вкладка «Репозитории» сохраняет полноценный список.
- «Активность» показывает ранжированные доступные репозитории и историю реальных коммитов, Issues, PR и других доступных событий.
- Сортировка репозиториев основана на максимуме последнего push, самого свежего полученного события и последнего фактического открытия этого репозитория пользователем в GitHubble. Дата создания используется лишь для ещё неактивных проектов. Более старый неактивный репозиторий автоматически сдвигается вниз, когда в других происходят свежие действия.
- Карточка коммита показывает реальную первую строку сообщения (при feat/fix добавляется русская подпись), тело сообщения, сокращённый SHA, автора, локальную дату и время. Нажатие открывает конкретный коммит на официальном GitHub.
- Доступны фильтр «Коммиты», группировка по местным календарным дням и поэтапная загрузка длинной ленты.

## Источники данных и ограничения
- Старый эндпоинт `/users/{login}/events` показывает в основном публичную активность. Поэтому он не мог служить надёжной историей изменений приватного GitHubble. В RC4.2.1 добавлен авторизованный вызов GitHub `/repos/{owner}/{repo}/commits` для репозиториев, доступных текущему GitHub App user token.
- Чтобы избежать сотен запросов и превышения лимитов API, автоматически проверяются 20 наиболее недавно активных/открывавшихся репозиториев, до 40 коммитов каждого за последние 14 дней, преимущественно история default branch. Остальные репозитории отображаются в ранжированном списке, но их коммиты могут не попасть в первичную ленту. Лента ограничена 180 последними событиями.
- Отсутствующие права `Contents: Read`, приватные репозитории вне установки GitHub App и ошибки/лимиты API отражаются в строке состояния; они не интерпретируются как отсутствие коммитов. При ошибке обновления сохраняется последняя ранее загруженная лента.
- Дата группировки — локальная дата на Android; поэтому коммит на границе UTC и МСК может оказаться 20 либо 21 сентября в соответствии с часовой зоной телефона.
- Сведения взяты из сообщений реальных коммитов. Приложение не генерирует собственный выдуманный changelog и не объявляет, что каждая описанная работа проверена в работающем APK.
- Отображаемые приватные данные, история просмотров и кэш активности отделены по аккаунту и удаляются при явном выходе из него.

## Приёмка на устройстве
1. Открыть «Активность», дождаться загрузки и проверить репозиторий GitHubble в верхней части ранжирования после последних коммитов.
2. Проверить в ленте реальные коммиты 20–21 сентября в местном часовом поясе, короткий SHA, автора, полное сообщение и переход к коммиту.
3. Открыть старый проект: он поднимается в списке по факту использования; после новых действий в других проектах опускается.
4. Проверить поведение при недоступном Contents: Read и в офлайне без выдачи пустого результата за достоверный.
5. Убедиться, что на главной нет блока пяти проектов, а в Центре сборок нет кнопки «Настроить».
