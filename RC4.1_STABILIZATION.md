# GitHubble RC4.1 — стабилизация

Основа: RC4.0, commit `6a26bafd751d5913487f01cef906f7843df30556`.
Релиз: `1.0.0-rc4.1`, versionCode `46`. Один атомарный коммит в main.

## Реализовано
- GitHub Actions: автоматическая сборка только при push в main; ручной запуск и PR на main по-прежнему поддерживаются. Concurrency отменяет устаревший запуск для той же ветки.
- Центр сборок: при периодической проверке не более одного нового уведомления на отслеживаемый репозиторий; более позднее уведомление этого репозитория заменяет старое. История запусков остаётся доступной в приложении и на GitHub.
- Billing: отдельная быстрая загрузка официального использования Actions. Длительное сканирование артефактов/кэша запускается отдельной кнопкой, использует выделенный executor, показывает ход, поддерживает остановку и ясно маркирует частичный результат, нехватку разрешений и лимит 100 репозиториев.
- Асинхронные ответы Billing/инвентаризации не изменяют другой экран и не показывают сведения предыдущей сессии.
- Сохранены Device Flow с вставкой восьмизначного кода и официальный Chrome Custom Tab без нижней полоски.

## Границы реализации / проверка на устройстве
- Android JobScheduler не доставляет настоящие мгновенные push; MIUI/Doze могут задерживать уведомления.
- Локальные уведомления от старых версий, уже появившиеся в шторке, новая версия автоматически не удаляет.
- Инвентаризация ограничена первыми 100 принадлежащими аккаунту репозиториями; найденные байты не тождественны billing-квоте.
- Из-за отключённой постоянной подписи Release публикуется только Debug APK и неподписанный Release APK до настройки signing secrets.
- Приёмка на устройстве: вставка восьми символов GitHub, отсутствие нижней полоски, одиночное уведомление после нескольких запусков одного проекта, быстрое открытие Billing, остановка долгого сканирования, переключение экранов при работающем запросе.
- Сквозные проверки двух аккаунтов, 100+ private repos, реального Copilot entitlement и PR editor/review — задачи следующих этапов.
