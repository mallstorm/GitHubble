# GitHubble 0.25.0 — этапы 61–72

Версия: `0.25.0-alpha-translation-beta-audit`  
Package: `app.githubble.mobile`  
minSdk: 28  
target/compileSdk: 36

## 61. Единый перевод GitHub-контента

Добавлена единая панель «Оригинал / Перевести / Русский» для:

- README;
- описания профиля;
- Issues и комментариев;
- Pull Requests, комментариев и reviews;
- Discussions и ответов;
- описаний Releases.

Панель показывает определённый язык, состояние кэша, прогресс и ошибку с повтором.

## 62. Автоматическое определение языка

Реализован автономный `LanguageDetector` без отправки текста сторонним службам. Различаются русский, украинский, латиница, китайский, японский, корейский и арабский текст. Определение используется только для UX и решения, предлагать ли перевод.

## 63. Несколько переводчиков

В настройках доступны:

- универсальный JSON endpoint;
- OpenAI-compatible Chat Completions endpoint;
- LibreTranslate.

Настраиваются endpoint, модель, API-ключ, размер части и автоматический перевод.

## 64. Защищённое хранение ключей

Endpoint, модель и API-ключ переводчика сохраняются через `SecureStore`, использующий Android Keystore и AES-GCM. Ключи провайдеров не входят в APK или исходники.

## 65. Перевод длинного Markdown

`TranslationEngine` разбивает документ по границам строк на части примерно по 3600 символов, последовательно переводит их, показывает прогресс и собирает результат без обрезания длинных README или release notes.

## 66. Сохранение GFM и технических фрагментов

Перед переводом защищаются плейсхолдерами:

- fenced/inline code;
- URL;
- пути и команды;
- JSON/YAML-подобные строки;
- версии и хеши;
- HTML-теги.

URL внутри Markdown-ссылок защищается отдельно, а название ссылки остаётся переводимым. После ответа плейсхолдеры восстанавливаются.

## 67. Кэш по SHA и времени обновления

Создана SQLite-база `githubble_translation_cache.db`. Ключ учитывает:

- SHA-256 исходного текста;
- `updated_at`/маркер обновления;
- целевой язык;
- provider + endpoint + model.

Кэш ограничен 250 последними записями и очищается из настроек.

## 68. Подсветка исходного кода

Новый `CodeHighlighter` поддерживает базовую подсветку Java, Kotlin, JavaScript/TypeScript, Python, C/C++, Go, Rust, XML, JSON и YAML без внешних библиотек.

## 69. Навигация по исходникам

Viewer файлов получил:

- поиск в файле;
- подсветку совпадения;
- переход к номеру строки;
- копирование выбранного диапазона строк;
- страницы по 400 строк;
- предыдущую/следующую страницу.

## 70. Пагинация

Добавлена подгрузка следующих страниц для глобальных и репозиторных Issues/PR/Releases, поиска репозиториев, собственных репозиториев, организаций, подписчиков/подписок, PR commits/files, Projects v2 и Discussions. REST использует page/per_page, GraphQL — `pageInfo.endCursor`.

## 71. Диагностика фонового наблюдения

Добавлен экран диагностики:

- наличие JobScheduler-задачи;
- статус системной оптимизации батареи;
- предупреждение для Xiaomi/Redmi/POCO;
- время последнего запуска, успеха и результат;
- ручная тестовая проверка;
- переходы в системные настройки приложения и энергосбережения.

`TrackingJobService` фиксирует старт, завершение, успех и ошибку каждой фоновой проверки.

## 72. Beta-аудит

Выполнены:

- offline Gradle build;
- компиляция Java/Kotlin-части;
- проверка package/version/minSdk/targetSdk;
- zipalign;
- APK Signature Scheme v3 verify;
- поиск встроенных private keys, GitHub tokens, OpenAI keys и Client Secret;
- JVM-проверки LanguageDetector;
- JVM-проверки защиты GFM, восстановления плейсхолдеров и chunking.

## Ограничения

- Для реального перевода пользователь должен настроить собственный endpoint/API-ключ. В приложение не встроен общий платный ключ.
- Качество перевода зависит от выбранного провайдера. Движок защищает технические элементы, но некорректный провайдер теоретически может изменить плейсхолдер.
- Инструментальная проверка выполнена без физического Android-устройства. MIUI JobScheduler, реальные API permissions и длинные документы нужно подтвердить на телефоне.
- Архитектура всё ещё содержит крупный `MainActivity`; перед stable 1.0 нужна дальнейшая декомпозиция и instrumentation tests.
