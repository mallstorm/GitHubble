# GitHubble — отчёт реализации этапов 125–128

Версия: `1.0.0-rc3.1-stage125-128-advanced-search`  
versionCode: `35`

## Цель прохода

Расширить уже реализованный `RU ✦` с поиска репозиториев на остальные основные поисковые поверхности GitHub и дать пользователю русскоязычный визуальный конструктор фильтров без отдельного backend.

## Этап 125 — Issues / Pull Requests

Реализовано:
- новый тип поиска `Issues/PR` на общем экране поиска;
- русский интеллектуальный запрос проходит через существующий технический словарь и ограниченное расширение вариантов;
- поиск выполняется через GitHub Search Issues API;
- единый список различает `Issue` и `PR`, открывает существующий нативный экран Issue либо Pull Request;
- визуальные фильтры: `Все / Issues / Pull Requests` и `Любое / Открытые / Закрытые`;
- GitHub-квалификаторы проверяются по отдельному allow-list для Issues/PR;
- несовместимые квалификаторы не отправляются и явно показываются пользователю в блоке объяснения поиска.

## Этап 126 — пользователи и организации

Реализовано:
- тип поиска `Люди`;
- единый поиск GitHub users/organizations;
- русский запрос может быть расширен `RU ✦` так же, как репозиторный;
- фильтр `Пользователи и организации / Только пользователи / Только организации`;
- дополнительное ограничение по login;
- пользователь открывается в нативном профиле разработчика GitHubble;
- организация открывается на официальной странице GitHub;
- результаты нескольких вариантов объединяются и дедуплицируются по login.

## Этап 127 — поиск кода

Реализовано:
- тип поиска `Код`;
- GitHub REST code search;
- карточка результата показывает файл, репозиторий и полный путь;
- результат открывает найденный файл на GitHub;
- безопасный allow-list legacy code-search qualifiers: `in:`, `repo:`, `user:`, `org:`, `language:`, `path:`, `extension:`, `filename:`, `size:`, `fork:`;
- квалификаторы от других поисковых поверхностей, например `stars:`, отбрасываются до запроса и показываются как несовместимые;
- в русский словарь добавлены технические термины для кода: токен, обработка, обработчик, функция, метод, класс.

Актуальность qualifier-модели сверена с GitHub Docs 2026: REST Code Search использует legacy code search syntax.

## Этап 128 — визуальный конструктор фильтров

На экране поиска добавлена строка областей:

`Репо | Issues/PR | Код | Люди`

Сразу под ней расположен компактный блок `Фильтры`.

### Репозитории
- язык;
- минимум stars;
- дата обновления (компилируется в `pushed:>=YYYY-MM-DD`);
- владелец `user:` или организация `org:`;
- topic.

### Issues / PR
- Issue / Pull Request / оба;
- open / closed / любое состояние.

### Код
- язык;
- user/org.

### Люди
- пользователь / организация / оба;
- login.

Выбранный режим и фильтры сохраняются локально в SharedPreferences. `RU ✦` остаётся независимым переключателем и работает во всех четырёх областях.

## Компилятор запросов

Добавлены:
- `SearchMode.java`;
- `SearchFilters.java`;
- `AdvancedSearchPlanner.java`.

`AdvancedSearchPlanner` отделяет смысловую часть от квалификаторов, проверяет квалификаторы по выбранной поисковой поверхности, выполняет русское семантическое расширение и только после этого добавляет визуальные фильтры.

Также поддержаны динамические современные qualifier-префиксы:
- repository custom properties: `props.*`;
- issue fields: `field.*`.
