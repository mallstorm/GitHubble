# RC4.2.9 — Этап 1 модернизации поиска

## Исправление авторизации
- Код GitHub HTTP 401 от конкретного эндпоинта больше **не** помечает весь аккаунт как вышедший: глобальный reauth-flag устанавливается только при ошибке GET /user.
- В расширенном поиске при 401 допускается одна попытка обновить **уже истёкший** токен и повторить текущий запрос; 401 только для code-search с действующим токеном не инициирует бесконечные refresh-запросы и не уничтожает сессию.
- Пользователь получает отдельные сообщения по 401, 403, 422 и 429, кнопку возврата к сохранённому запросу, а при 401 — кнопку переподключения GitHub. Не выдавать любой 401 как доказательство недействительной сессии.
- Запрос сохраняется локально в `search_draft_query`, чтобы пользователь мог вернуться к полю ввода после ошибки или прохождения Device Flow. Новые разрешения и сервисы не добавлены.

## Поиск имени файла по репозиторию
- `Поиск → Найти файл по имени`: выбрать репозиторий из синхронизированного списка, либо ввести `owner/name` вручную. Поиск также доступен непосредственно из экрана «Файлы» конкретного репозитория, с сохранением выбранной ветки.
- Поиск идёт по путям файлов выбранного репозитория через Git Trees API (`recursive=1`), включая файлы приватного репозитория при наличии текущих разрешений. Это **не** полнотекстовый поиск содержимого и не обход авторизации поиска кода.
- Выдача: совпадение по всем словам в имени/пути, приоритет точного совпадения имени, нативное открытие файла, максимум 80 карточек. Если GitHub помечает дерево как `truncated`, явно предупреждаем о неполном охвате. Большие репозитории требуют уточнения запроса; поиск не сканирует устройство.
- Голосовой ввод на странице поиска имени файла использует тот же системный распознаватель ru-RU/en-US, что и основной поиск, с кнопкой остановки.
