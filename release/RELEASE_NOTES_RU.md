# GitHubble 1.0.0-rc4.2.31

Версия 1.0.0-rc4.2.31, versionCode 78. Агентский чат: действия, документы и поле ввода.

- Компактная лента задачи с пиктограммами инструментов, именами файлов, итерациями и временем в формате минуты:секунды. Длительность сохраняется после завершения.
- Завершённые чтения сгруппированы; старые системные записи объединяются визуально без удаления истории.
- Поле ввода объединяет оформление OmniChat и GitHubble. Кнопка «План» удалена: агент самостоятельно планирует шаги. Отдельные разрешения на запись и подтверждение изменений сохранены.
- CommonMark/GFM: заголовки, вложенные списки, задачи, таблицы с горизонтальной прокруткой, цитаты, ссылки и блоки кода с подсветкой и копированием.
- Документ и Markdown-исходник открываются отдельно; доступно сохранение .md. Ответы больше не обрезаются молча до 6000 символов; лимит истории ответа — 80 000 символов, старые сообщения архивируются.
- Счётчики фактических изменений +N −N и просмотр «Изменения / До / После» по защищённым снимкам файлов. Предложение, локальная запись и публикация GitHub различаются.
- Реальный поток текста передаётся из поддерживаемых транспортов; аргументы инструментов и reasoning не попадают в preview.
- Задача сохраняется при смене конфигурации, обновления не пересоздают поле ввода. Контекст аккаунта и диалога проверяется перед инструментами. После смерти процесса отсутствует ложное бесконечное выполнение.
- Каталог инструментов учитывает готовность Workspace. Ошибки локальных инструментов не маскируются под OAuth-ошибки провайдера.

ARM64, Android 9+. R8 и Xray/VLESS сохранены. Release candidate: реальные аккаунты провайдеров и операции GitHub на физическом телефоне требуют отдельной приёмки.

# GitHubble RC4.2.2 — процесс GitHub PR

- Версия 1.0.0-rc4.2.2, versionCode 49.
- Рабочие ветки → PR → проверки Android checks → Squash and merge в main → один итоговый APK и архив исходников.
- Для PR и ручных CI-запусков APK/ZIP не публикуются; Android checks запускает компиляцию, lint, unit и инструментальные тесты.
- В Центре сборок PR-проверки остаются в истории, но не создают уведомлений о пользовательском APK и не участвуют в автоматическом скачивании.
- Удалён устаревший workflow импорта ZIP, который мог самостоятельно коммитить прямо в main. Импорт исходников теперь оформляется обычным PR.
- Добавлены CONTRIBUTING, шаблон Pull Request и инструкции по защите main, review и безопасному откату.

## Важное ограничение

Настройка обязательной branch protection ещё не выполнена: GitHub API вернул HTTP 403 для правил приватного репозитория на текущем плане и для чтения параметров защиты. До изменения условий GitHub нельзя технически исключить прямой push в main; команда соблюдает PR-процесс добровольно. Проверку на реальном телефоне нельзя заменить успешным CI.

# GitHubble RC4.1 — стабилизация

- Версия 1.0.0-rc4.1, versionCode 46. Основная ветка: main.
- Один автоматический запуск CI после пакетного коммита в main: push в рабочие/резервные ветки не создаёт промежуточных Android-сборок; устаревший запуск той же ветки отменяется.
- Центр сборок группирует новые уведомления по репозиторию: не больше одного за проверку и одно место в шторке.
- Billing загружается независимо от инвентаризации Actions. Хранилище проверяется отдельным действием с ходом, отменой и явной отметкой частичного результата.
- При переходе на другой экран либо смене аккаунта устаревшие данные сканирования не вставляются в текущий интерфейс.
- Device Flow и копирование восьмизначного кода сохранены; дополнительная нижняя панель браузера удалена.

## Ограничения

- На устройстве владельца предстоит проверить длительное сканирование при 100+ репозиториях и работу JobScheduler на MIUI.
- Подписанный Release APK создаётся только при настроенном постоянном ключе подписи.

# GitHubble 1.0.0 RC4.0 — модернизация и стабилизация

- единый `RepositoryStore`: Home и «Мои репозитории» используют один snapshot;
- пагинация более 100 репозиториев, stale-while-revalidate и явное состояние ошибки;
- HTTP/ETag cache изолирован по аккаунту, 304 без тела больше не маскируется;
- OAuth сохраняет expiry/refresh metadata, поддерживает безопасную ротацию и reauth после 401;
- офлайн-очередь привязана к аккаунту, repository и idempotency key, имеет TTL;
- logout очищает приватный кэш и очередь текущего аккаунта;
- устаревший force reset HEAD удалён из навигации; default branch защищена;
- очистка Actions инвалидирует каждый затронутый репозиторий;
- неизвестное состояние star/follow не показывается как `false`;
- bottom navigation: Главная, Репозитории, Поиск, Активность, Профиль;
- исправлены accessibility touch targets и семантика без принудительного focus order;
- диагностический экспорт использует whitelist и не выгружает приватные payload;
- версия вынесена в `version.properties`, UI/User-Agent/artifacts читают BuildConfig;
- CI выполняет tests, lint, debug/release build и emulator regression suite;
- release без постоянного signing keystore блокируется.

## Уточнение кандидата Unified Agent перед выпуском

Исправлено продолжение CI после публикации исправленного коммита. Неопределённый
workflow dispatch нельзя подтвердить старым запуском или запуском другого workflow.
Приёмка и последовательность выпуска описаны в docs/unified-agent/ACCEPTANCE.md.
