# GitHubble 1.0.0-rc4.2.28

Оптимизирован размер ARM64 Release APK при сохранении встроенного Xray/VLESS и возможностей модернизированной версии.

- Включены R8 и удаление неиспользуемых ресурсов. Из Xray удаляются отладочные символы; исполняемый код и загружаемые данные сверяются с оригинальной библиотекой.
- Размер Release до подписи уменьшен примерно с 60,0 до 37,8 МБ (−37%). Карта R8 и нативные символы сохраняются отдельно для диагностики.
- Сохранены JNI/reflection-контракты Xray и конструкторы Room, необходимые для запуска WorkManager после оптимизации.
- Добавлена проверка настоящего minified Release на Android 13: основные экраны, JNI и передача данных через SOCKS → VLESS → локальный echo-сервер.

Версия 1.0.0-rc4.2.28, versionCode 75. ARM64, Android 9+. Release candidate: физический телефон, внешний VLESS/TLS/REALITY-сервер и все OAuth/AI-подписки не покрываются этой проверкой. Постоянная подпись проекта позволяет обновить предыдущий подписанный Release с сохранением данных.

# GitHubble 1.0.0-rc4.2.27

Стабилизация модернизированной версии PR #22/#23: Git Agent, Workspace и новые настройки сохранены.

- Исправлена изоляция аккаунтов при сетевых запросах, кэшировании и replay очереди.
- Старый API-кэш очищается при обновлении: ответы, сохранённые прежним клиентом, загружаются заново. Пользовательские файлы, ключи и очередь сохраняются.
- Убраны опасные автоматические повторы записей; неизвестный результат требует проверки GitHub.
- Офлайн-очередь не удерживает блокировку во время сети и проверяет свежую версию объекта.
- Полное удаление данных очищает всё хранилище приложения средствами Android и закрывает приложение.
- Исправлена загрузка файлов приватных Releases без передачи OAuth CDN.
- Устаревшие ответы файловых экранов не меняют новый экран; исправлено кодирование путей.
- Обновлены Wrapper, release scripts, контрольные суммы и проверки CI.

Release candidate, ARM64, Android 9+. Физический телефон, реальные AI-подписки и все OAuth-сценарии не покрываются CI. Подписанный Release APK использует постоянный сертификат проекта; Debug предназначен только для тестирования.

# GitHubble RC4.2.3 — встроенный просмотр коммитов

- Версия 1.0.0-rc4.2.3, versionCode 50.
- Карточки коммитов в «Активности», списках репозитория и PR открываются внутри приложения, а не в браузере.
- Встроенный экран показывает автора, сообщение и SHA коммита, изменённые файлы, статистику добавлений/удалений, безопасный построчный diff с подсветкой и раскрытием файлов.
- Работа с доступными приватными репозиториями — через авторизованный GitHub API. Для больших/бинарных diff используются явные ограничения и сообщения, не пустой экран.
- Сохранён PR workflow: проверка pull request без публикации APK, итоговая сборка после Squash and merge в main.

## Проверка на телефоне

Откройте один из коммитов GitHubble в «Активности», раскройте изменённые файлы, проверьте цветовую подсветку строк, возврат назад, открытие SHA из списка коммитов PR и репозитория. Для приватных файлов потребуется GitHub App Contents: Read.

# GitHubble RC4.2.2 — процесс GitHub PR

- Версия 1.0.0-rc4.2.2, versionCode 49.
- Рабочие ветки → PR → проверки Android checks → Squash and merge в main → один итоговый APK и архив исходников.
- Для PR и ручных CI-запусков APK/ZIP не публикуются; Android checks запускает компиляцию, lint, unit и инструментальные тесты.
- В Центре сборок PR-проверки остаются в истории, но не создают уведомлений о пользовательском APK и не участвуют в автоматическом скачивании.
- Удалён устаревший workflow импорта ZIP, который мог самостоятельно коммитить прямо в main. Импорт исходников теперь оформляется обычным PR.
- Добавлены CONTRIBUTING, шаблон Pull Request и инструкции по защите main, review и безопасному откату.

## Важное ограничение

Настройка обязательной branch protection ещё не выполнена: GitHub API вернул HTTP 403 для правил приватного репозитория на текущем плане и для чтения параметров защиты. До изменения условий GitHub нельзя технически исключить прямой push в main; команда соблюдает PR-процесс добровольно. Проверку на реальном телефоне нельзя заменить успешным CI.

# GitHubble RC4.2.1 — история изменений

- Версия 1.0.0-rc4.2.1, versionCode 48.
- Убрана кнопка «Настроить» из Центра сборок и блок пяти репозиториев с главной.
- Во вкладке «Активность» репозитории отсортированы по времени последнего push, события или открытия в GitHubble; дата создания — только резервный критерий.
- Добавлена история реальных коммитов с авторизованным доступом к разрешённым private-репозиториям: сообщение, SHA, автор, локальные дата/время, переход на страницу коммита.
- Фильтр «Коммиты», группировка по местным дням, постраничное отображение истории; ошибки прав доступа и частичное покрытие обозначаются явно.
- Кэш событий и история открытий изолированы по аккаунту и удаляются при выходе.

## Ограничения
- Автозагрузка коммитов охватывает до 20 наиболее активных проектов, максимум 40 коммитов каждого за 14 дней (обычно default branch), а не всю историю GitHub. Требуется GitHub App Contents: Read.
- Удобство экрана и наличие приватных коммитов необходимо проверить на реальном аккаунте; тесты на эмуляторе не выдают приватный OAuth-токен.
- Подписанный релиз требует постоянный signing keystore.

# GitHubble RC4.2 — интерфейс и навигация

- Версия 1.0.0-rc4.2, versionCode 47.
- Пять единых корневых вкладок: Главная, Репозитории, Поиск, Активность, Профиль. Настройки доступны из профиля.
- На главной отображаются до пяти реальных репозиториев аккаунта, независимо от декоративных быстрых ссылок.
- Репозитории: список/плитки, сворачиваемые языковые фильтры, порционная отрисовка по 24 карточки.
- Центр сборок: компактные действия, фильтры по статусу и порционная история запусков.
- Поздние ответы загрузки отдельного репозитория не рисуются поверх другого экрана/аккаунта.
- Device Flow, полная вставка восьмизначного кода и отсутствие нижней браузерной полоски сохранены.

## Ограничения

- Для UI-изменений требуется приёмка на Android/MIUI; успешный CI не подтверждает удобство конкретного устройства.
- Подписанный Release APK создаётся только при наличии постоянного ключа в GitHub Secrets.

# GitHubble RC4.1 — стабилизация

- Версия 1.0.0-rc4.1, versionCode 46. Основная ветка: main.
- Один автоматический запуск CI после пакетного коммита в main: push в рабочие/резервные ветки не создаёт промежуточных Android-сборок; устаревший запуск той же ветки отменяется.
- Центр сборок группирует новые уведомления по репозиторию: не больше одного за проверку и одно место в шторке.
- Billing загружается независимо от инвентаризации Actions. Хранилище проверяется отдельным действием с ходом, отменой и явной отметкой частичного результата.
- При переходе на другой экран либо смене аккаунта устаревшие данные сканирования не вставляются в текущий интерфейс.
- Device Flow и копирование восьмизначного кода сохранены; дополнительная нижняя панель браузера удалена.

## Ограничения

- На устройстве владельца предстоит проверить длительное сканирование при 100+ репозиториях и работу JobScheduler на MIUI.
- Подписанный Release APK создаётся только при настроенном постоянном ключе подписи.

# GitHubble 1.0.0 RC4.0 — модернизация и стабилизация

- единый `RepositoryStore`: Home и «Мои репозитории» используют один snapshot;
- пагинация более 100 репозиториев, stale-while-revalidate и явное состояние ошибки;
- HTTP/ETag cache изолирован по аккаунту, 304 без тела больше не маскируется;
- OAuth сохраняет expiry/refresh metadata, поддерживает безопасную ротацию и reauth после 401;
- офлайн-очередь привязана к аккаунту, repository и idempotency key, имеет TTL;
- logout очищает приватный кэш и очередь текущего аккаунта;
- устаревший force reset HEAD удалён из навигации; default branch защищена;
- очистка Actions инвалидирует каждый затронутый репозиторий;
- неизвестное состояние star/follow не показывается как `false`;
- bottom navigation: Главная, Репозитории, Поиск, Активность, Профиль;
- исправлены accessibility touch targets и семантика без принудительного focus order;
- диагностический экспорт использует whitelist и не выгружает приватные payload;
- версия вынесена в `version.properties`, UI/User-Agent/artifacts читают BuildConfig;
- CI выполняет tests, lint, debug/release build и emulator regression suite;
- release без постоянного signing keystore блокируется.
